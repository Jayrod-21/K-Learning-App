## Findings

### BLOCKER
None.

### SHOULD-FIX
- Today.tsx:472-499 (`useCenterOnMountRef` doc comment) describes the `firedRef` guard as the thing preventing re-centering on later re-renders (attempt-history fetches resolving). In practice the guard is a defense-in-depth belt only — the real reason re-renders never re-invoke `scrollIntoView` is that the returned callback is `useCallback(..., [])`-memoized so React never re-fires a ref callback whose identity is unchanged and whose host DOM node hasn't been recreated. Worth a one-line clarification so a future maintainer doesn't assume the guard is load-bearing and, e.g., "simplify" it away, which would be safe today but would stop being safe if the callback were ever accidentally given a non-empty dep array.

### NIT
- Today.test.tsx:146-174 / 235-271 (the two "centers … once" tests) render only once and never force a second re-render before asserting the call count. Given the mechanism is a stable-identity ref callback, a genuine "does it survive a later re-render" regression (e.g., someone adds a dependency to the `useCallback`) wouldn't be caught by these tests as written — they'd still pass because there's only ever one render in the test. Not required for this PR, but a follow-up test that triggers a second `rerender()` after an async state update (e.g., flushing `grammarAttempts`/`readingAttempts` mocks) would close the gap and directly protect the exact regression the doc comment warns about.
- Today.css:9-36 / Today.tsx:472-499 — the F-188 root-cause comment and the `useCenterOnMountRef` comment are both excellent and unusually thorough, but they're long enough (25+ lines each) that they're starting to compete with the code for attention. Not asking for a trim, just flagging that this file's comment-to-code ratio is now quite high — a pattern to watch across the redesign, not a defect in this PR.

### PRAISE
- Today.css:34-36 / PageHubHeader.tsx:97-99 / PageHubHeader.css:35-39 — the F-188 fix is exactly the right shape: it hides the nested `.km-dancheong-rail` (already `aria-hidden="true"` in DancheongRail.tsx:49, so no a11y regression from removing it visually) scoped three levels deep (`.km-today__hub .km-hubheader__rail-divider .km-dancheong-rail`), and deliberately leaves the `.km-hubheader__rail-divider` wrapper's own box (`height: 26px; margin: 0 0 4px`) untouched so the reserved spacing is preserved byte-for-byte. Verified `.km-today__hub` is a className forwarded only by Today.tsx (grep across all 18+ `PageHubHeader` call sites — Diagnostic, Images, Chat, Grammar, Progress, Mistakes, Hanja, Reading, Review, Tickets, Topik, Uploads, UploadViewer, Writing, Ttmik, ReviewLibrary, Settings, plus Today — confirms none of the others carry `km-today__hub`), so the fix cannot leak to any other page. This is a model example of scoped, minimal-blast-radius CSS.
- Today.tsx:500-507 — `useCenterOnMountRef` using a ref callback rather than `useEffect` is the correct call given Carousel 2's conditional mount timing (items only exist once `today.data` resolves), and using the browser's native `scrollIntoView({inline:'center'})` instead of hand-rolled scroll math correctly cooperates with the existing `scroll-snap-align: center` on `.km-today__peekItem` (Today.css:314) rather than fighting it. Leaving `behavior` at its default (instant, not `'smooth'`) is the right choice — confirmed no page-wide `scroll-behavior: smooth` exists that could turn this into an unwanted animated slide on load (the only `scroll-behavior` rule in the app is the reduced-motion `!important auto` override at `styles/index.css:606`, which is a no-op here either way).
- Today.css:52-61 (F-187) — scoping the gap reduction to a `--topik` modifier on only the TOPIK `<h2>`, rather than lowering the shared `.km-today__sectionTitle` margin-top, is the correct minimal fix. Confirmed via source: the modifier rule is declared after the base rule with equal specificity (both single-class selectors), so CSS cascade order correctly lets it win for the TOPIK heading only, while Review&drills → Suggested-learning keeps the untouched shared 12px.
- Today.test.tsx:889-1000 (pre-existing Wave 2 deep-link tests) — verified these locate tiles by accessible name/text (`getByRole('button', { name: /도시화와 환경/ })`, `/KBS/`, `/Paragraph in/`, etc.), never by index, so the F-190 DOM reorder cannot silently break the Reading/Listening/Writing or TOPIK-resume (`?mode=mock`) deep-link tests. Grepped the whole file for `getAllByRole('button')[` (positional indexing) and found zero hits — the reorder is safe against every existing assertion in this file, not just the new ones.
