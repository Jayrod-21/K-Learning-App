### SHOULD-FIX

- **SF-1 — ReviewDictionary error path has no retry.** ReviewDictionary.tsx:277-278 renders `<ErrorCard message={error} />` without `onRetry`; the page has no `reloadTick`/refetch mechanism at all. The sibling ReviewVocab added exactly this (ReviewVocab.tsx:214, 293-295, 342 + the Retry test at test:395-444) — the bar for this phase is "real error + retry", and this page was substantially rewritten this phase (228 lines changed). A failed page-2 fetch or transient 500 leaves the user with no recovery except mutating a filter. (Pre-existing on `rebuild`, but the rewrite was the moment to close it.) Fix: mirror ReviewVocab's `reloadTick` pattern; keep the 503 "dictionary isn't available yet" case retry-less or retry-capable as desired.
- **SF-2 — F-053 backend follow-up not actually filed in-tree.** The stub's comment says the backend work is a "proposed ticket in the P3B report" (ReviewVocab.tsx:194-196), but `docs/phase3b/` contained no report at review time and `BUGS_AND_FEATURES.md` has no entry for save-path provenance + `GET /vocab/saved-from-uploads` (its F-053 entry, line 861, is the client feature itself). The bar was "backend ticketed". Fix: add the backend follow-up as a real entry (BUGS_AND_FEATURES.md or the P3B report) and point the code comment at the concrete ref.
- **SF-3 — ReviewDictionary test coverage is thin vs its new behavior surface.** Untested: (a) the typed-search-supersedes-초성 effect (ReviewDictionary.tsx:147-152) — a regression here silently double-filters browse results; (b) the error path incl. the 503 "dictionary isn't available yet" copy (lines 204-213); (c) the pager (Prev/Next offsets, range copy) on either backend; (d) 초성 state surviving a genre pivot and reappearing pressed on clear. The vocab sibling sets the standard (windowing, retry, reset assertions); this page should meet it.

### NIT

- **N-1 — Transient stale-parameter fetch on compound state changes.** Changing a filter while `offset > 0` fires the fetch effect once with (new filter, old offset) in the same commit as the `setOffset(0)` reset effect; the follow-up render aborts and refires correctly (ReviewVocab.tsx:240-291). Same shape in ReviewDictionary when typing while a 초성 is active (setInitial(null) effect → duplicate fetch; ReviewDictionary.tsx:141-219). Functionally safe — per-fetch abort + `aborted` guards prevent any stale paint — but each transition costs one wasted, immediately-aborted request. Consider deriving offset-reset into the fetch effect (e.g., compute effective offset from a filter-keyed ref) if it ever matters; fine to leave.
- **N-2 — AddToListSheet's AbortController doesn't abort the request.** `vocabService.listLists()` takes no signal (services/vocab.ts:308-312), so the controller at ReviewVocab.tsx:448-450 only gates the `.then` state writes (which it does correctly — no setState-after-unmount). The code reads as abort-wired when it isn't. Add an optional `signal` param to `listLists` or drop the controller for a plain `alive` flag with a comment.
- **N-3 — DIFFICULTY_OPTIONS hardcoded; shared `VOCAB_LEVEL_FILTERS` now orphaned.** ReviewVocab defines its own 3-band list (ReviewVocab.tsx:95-105) while `lib/libraryFilters.ts:30` still exports a 2-band `VOCAB_LEVEL_FILTERS` with no remaining production consumer (grep-verified) and a now-stale doc comment ("curated vocab corpora carry only beginner/intermediate"). ReviewGrammar meanwhile derives from the shared `GRAMMAR_LEVEL_FILTERS` (ReviewGrammar.tsx:59, 89). Either update the shared list to 3 bands and consume it, or delete the orphan — the deliberate 3-band decision itself is fine and well-documented (honest empty state, server enum verified at vocab.ts:70).
- **N-4 — No in-flight feedback when stale rows remain.** Both pages show the loading `role="status"` only when `rows.length === 0`; after a filter/page change with old rows on screen there is no `aria-busy`, dim, or indicator until the fetch resolves (ReviewVocab.tsx:332, ReviewDictionary.tsx:269). Keep-stale-while-loading is a fine pattern, but a lightweight `aria-busy` on the list container would help AT users.
- **N-5 — (out-of-scope service, noting for coordination) `createList` doesn't coerce the returned BIGINT `list.id`** through `numericId` the way `listLists`/`getListDetail` do (services/vocab.ts:314-319). Harmless on the F-048 path (the sheet closes without using the id), but a future consumer doing `newList.id === n` will miss. services/vocab.ts is unchanged this phase — flagging, not charging.

### PRAISE (fix-pass must not undo)

- **P-1 — The pagination honesty contract is real engineering, not comments.** `usePagination.remaining` = `min(step, headroom)` with the explicit warning against `total − visible` (usePagination.ts:36-43, 77), `ShowMore` re-documents the same contract (ShowMore.tsx:26-31), and ReviewVocab gates the server Pager behind `!canShowMore` precisely so "N–M of T" can never describe rows that aren't on screen (ReviewVocab.tsx:390-405). Three layers, one invariant.
- **P-2 — F-051 tests are genuinely behavioral.** Row 16 absent pre-expand, exact "Show more (15)" label, pager suppressed while collapsed, window collapse on filter change, and the failed-Next-page test asserting the error REPLACES stale page-1 rows and that no "31–60" range renders over them, then Retry lands real page 2 (ReviewVocab.test.tsx:340-445). Nothing tautological.
- **P-3 — F-053 is the model of an honest stub.** Unconditional `null` plus a comment that audits all three candidate data sources and names the fabrication it refuses to commit (ReviewVocab.tsx:175-199), plus a test pinning the absence. (Close the ticket-ref gap per SF-2.)
- **P-4 — `showGrammar={false}` skips the fetch, not just the render** (WeeklySuggestions.tsx:78-82), and the ReviewVocab test proves it by making the mock return grammar and asserting the service was never called (ReviewVocab.test.tsx:211-236). Backwards-compatible default, additive prop, zero churn for the P4 relocation.
- **P-5 — Two-backend discrimination in ReviewDictionary is type-honest.** The `ResultPage` tagged union (ReviewDictionary.tsx:73-77) makes it impossible to render a KRDICT row through the vocab renderer or vice versa, and the header comment states plainly that KRDICT has no genre column and the curated corpus is the only genre-tagged source. No pretend-merged corpus.
- **P-6 — Error-over-stale-rows precedence with its rationale inline** (ReviewVocab.tsx:336-342): the comment documents the exact swallowed-failure mode the old `rows.length === 0` gate caused. This is the kind of comment that prevents a regression during refactor.
- **P-7 — Select-boundary guards + native-select FilterSelect.** OOV values degrade to `'all'`/`null` before touching state or the wire (ReviewVocab.tsx:109-120, ReviewDictionary.tsx:66-70), and FilterSelect's native-`<select>`-on-purpose rationale (FilterSelect.tsx:5-11) buys the whole a11y contract for free.
