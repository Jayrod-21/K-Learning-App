# Review

**Scope:** `client/src/pages/Ttmik.tsx` (+ `Ttmik.test.tsx`), `client/src/lib/tapChain.ts` (+ `tapChain.test.ts`), `client/src/pages/Reading.tsx` (+ `Reading.test.tsx`, consumer of the new extraction), `client/src/types/domain.ts`.
**Branch:** `feat/ttmik-transcripts`, diffed against `rebuild` (merge-base `cac29b6`).
**Reviewer:** independent read-only pass; no code modified.

## Verdict

**APPROVE.** This is senior-level work. The headline requirement — a persistent `<audio>` element that survives Highlights ↔ Transcript sub-tab switches — is correctly implemented and is backed by a test that would actually fail on the naive (per-tab-remount) implementation. The `tapChain` extraction is a faithful, behavior-preserving refactor of `Reading.tsx` that also fixes a real latent bug (the abort signal previously wasn't threaded into the HTTP layer at all). No XSS sinks, no romanization leakage, no blocker-level findings.

Zero BLOCKERs. Two SHOULD-FIX (both pre-existing patterns this branch extends rather than introduces, but worth flagging since the branch is new surface area). Several NITs. Multiple PRAISE items.

## Findings

### BLOCKER
None.

### SHOULD-FIX

1. **`Tapword`'s "no threat model needed" docstring is now false, and nothing enforces the trust boundary it describes.** `client/src/components/Tapword.tsx:16-18` says the component needs no threat model because "`KoreanPassage` (the only caller) passes `tk.w` from the fixture, which is author-controlled." `Ttmik.tsx`'s `TapKorean` (`client/src/pages/Ttmik.tsx:866-896`) is now a second caller, and it renders raw server-corpus text (TTMIK/Iyagi transcript tokens), not fixture-authored text. React's default child-escaping still protects this — it's not exploitable — but the comment is stale and could mislead a future reader into believing `Tapword` handles only trusted input. Update the docstring to reflect that `children` is untrusted display text safe only because JSX children are always escaped (never rendered via `dangerouslySetInnerHTML`), and that this is a property of the component that must be preserved, not a property of its callers.

2. **Tab UI lacks `role="tabpanel"` / `aria-controls` wiring (both the Listen sub-tabs and the top-level corpus tabs).** `client/src/pages/Ttmik.tsx:227-247` and `:797-819` render `role="tablist"` / `role="tab"` but the panel below is a bare `<div>`/fragment with no `role="tabpanel"`, `aria-controls`, or `id` linkage, and there's no roving-tabindex/arrow-key navigation between tabs (WAI-ARIA APG Tabs pattern). This mirrors the pre-existing `Reference.tsx` tab idiom exactly (`client/src/pages/Reference.tsx:118-127`), so it isn't a regression introduced here — but this PR is net-new surface area repeating the same gap twice more, and the SENIOR_ENGINEER_BAR §2.6 WCAG 2.2 AA bar is P0 on keyboard operability. Worth a follow-up ticket to fix the shared tab idiom once, rather than continuing to copy it into every new tabbed screen.

### NIT

1. **`tsconfig.app.json` is missing the four bar-mandated strict add-ons** (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature`, `noImplicitOverride` — SENIOR_ENGINEER_BAR §2.1, P0). Project-wide, not introduced by this branch, but flagging since `ListenSentence`/`WordPopoverData` lean on optional (`?:`) fields throughout `domain.ts` and `WordPopover.tsx` — `exactOptionalPropertyTypes` would be a meaningful catch here specifically (e.g. `speaker?: string | null` is a double-null-able that `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` would tighten).
2. **`TapKorean` key uses array index + token text** (`client/src/pages/Ttmik.tsx:882,891`: `` `${i}:${tk.w}` ``/`` `${i}:sp` ``). Safe here in practice because `tokens` is derived once per immutable `text` via `useMemo` and never reordered/filtered — but it's an index-flavored key inside a component that could tempt future copy-paste into a genuinely reorderable list. A comment noting *why* index is safe here (stable, immutable-per-render source) would future-proof it; the code already has one but it's brief.
3. **Detail's `useEffect` fetch dependency `[selection, reloadTick]`** (`client/src/pages/Ttmik.tsx:596`) includes `selection`, but `DetailView` is always freshly mounted per `selectionKey` (parent keys on it at `Ttmik.tsx:222`), so `selection` is referentially stable for the component's whole lifetime and the dependency is inert. Harmless, but slightly misleading — a reader might infer the effect re-runs when `selection` mutates in place, which it never does (it's discriminated-union, replaced-not-mutated). Could drop `selection` from the deps with a comment explaining the key-based remount already guarantees freshness, or leave as defensive-but-redundant; either is fine, just flagging for awareness.
4. **`SentenceRow`/`HighlightsPanel`/`SentencesPanel`/`TranscriptPanel` list keys use `sentence.ordinal` / `line.ordinal` directly** (`client/src/pages/Ttmik.tsx:955,983,1089`) rather than a corpus-qualified key. Fine today (each panel renders exactly one corpus's rows, ordinals are unique within a unit), but if a future screen ever interleaves rows from two units in one list, a bare ordinal key would collide. Not actionable now.

### PRAISE

1. **The persistent-audio contract is implemented exactly as specified and is provably correct, not just documented as correct.** The `<audio>` element renders once at `client/src/pages/Ttmik.tsx:781-787`, strictly above and outside the `lessonTab === 'highlights' ? ... : ...` branch (`:821-833`), with `lessonTab` state held in `DetailView` itself (`:554`) rather than a per-tab child, and `DetailView` is keyed only on the *selection* (`selectionKey`, `:222`) — never on `lessonTab`. `Ttmik.test.tsx:258-282` asserts this with DOM-node reference equality (`expect(document.querySelector('audio')).toBe(audio)`) across two tab flips in both directions, plus `getTtmikLesson` call-count staying at 1 — a test that genuinely fails against the "audio nested in a tab-keyed subtree" anti-pattern this whole feature exists to avoid.
2. **The `tapChain` extraction is a clean, behavior-preserving refactor that also fixes a real bug.** Diffing `Reading.tsx` against `rebuild` shows `tokeniseSentence`/`isPlaceholderGloss`/`summariseEnrichment`/`buildWordPopover`/the inline slow-path chain moved verbatim into `lib/tapChain.ts` with no logic drift — and in the process, `resolveWordPopover` (`client/src/lib/tapChain.ts:234-266`) now threads `signal` into `lemmatize`/`defineEntry`/`enrich` (confirmed those three services actually forward it to axios's `signal` config: `client/src/services/lemmatize.ts:32-36`, `define.ts:31-38`, `enrich.ts:26-34`). Pre-refactor `Reading.tsx` only checked `ctrl.signal.aborted` *after* each await — it never canceled the in-flight HTTP request. This is a genuine reliability improvement riding along with the extraction, not scope creep: it fixes exactly the gap the old file's own docstring called out as future work (old `Reading.tsx:75-82`, per the `rebuild` diff).
3. **`buildAudioSrc`'s allow-list (`client/src/services/ttmik.ts:89`) is textbook defense-in-depth against a tampered response body.** Rather than a naive `startsWith('/')` prefix check (bypassable via backslash/`\t`/`\n` normalization to `//`, landing on an attacker origin), it anchors to the exact four route shapes with a full-string regex. The code comment names the specific bypass it defends against — exactly the SENIOR_ENGINEER_BAR §0 standard ("document the defended-against attack").
4. **Romanization removal is enforced at three independent layers, not just the UI.** The server route (`server/src/routes/ttmik.ts:132`) never selects romanization rows into highlights/sentences; the transcript loader mirrors this; and the UI's `TranscriptLineItem` `'romanization'` case (`client/src/pages/Ttmik.tsx:1021-1024`) still explicitly returns `<></>` with a comment noting it's now a defensive no-op. `Ttmik.test.tsx:245-246,301-302` assert the romanization text never renders even though the fixture data still carries the field on the wire (`LESSON_DETAIL.highlights[*].romanization`, `LESSON_DETAIL.transcript[2]`), which is exactly the right test shape — it doesn't just assert "the loader dropped it," it asserts "even if it arrives, the UI won't show it."
5. **Optimistic-flip/rollback for Add-to-bank was ported to `Ttmik.tsx` with the exact same contract as `Reading.tsx`**, including swallowing a close-aborted request (no rollback, no toast) vs. rolling back + fixed-copy toast on a real failure (`Ttmik.tsx:676-719` vs. `Reading.tsx:466-526`). No divergence found between the two call sites.
6. **Discriminated-union exhaustiveness is enforced with a compiler-checked `never`**, not just a runtime `default` (`TranscriptLineItem`, `client/src/pages/Ttmik.tsx:1066-1071`) — a new wire `kind` value fails `tsc`, not silently drops at runtime.
