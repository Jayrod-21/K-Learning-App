## Areas checked and found CLEAN (no real defect)

- **auth.ts (1153 lines, full read):** MFA challenge/consume/recovery-spend transactions are genuinely race-safe (spend+consume bound in one tx; confirm serialized on the `confirmed_at IS NULL` flip); enumeration-safe dummy verify; lockout math uses post-increment atomically; `PATCH /me` has optimistic concurrency + 23505 mapping; `conditionalRequireAuth` cannot be abused (a forged `challenge_token` just fails challenge lookup in `resolveEnrollAuth`).
- **IDOR:** every user-data query traced (`progress`, `vocab`, `vocabLists`, `conversation`, `images`, `hanja`, `settings`, `topik` responses/attempts, `diagnostic` runs/snapshots, `grammar` bank, `grammarDrill` attempts, `writing` series) is scoped to `getUserId(req)`; ownership misses uniformly 404. No client-supplied user id reaches any WHERE/INSERT.
- **SQL injection:** no user input interpolated anywhere; the `${…}` sites in SQL are fixed column lists, server-built `$n` placeholder lists (`topik.ts:423,1037`), server constants (`BUCKET_PREDICATE`, `MASTERY_MATURE_DAYS`, `ISO_WEEK_SQL`), or the validated-enum branch in `hanja.ts`. LIKE terms escaped via `escapeLikePattern` and still bound.
- **ttmik/iyagi streaming:** path traversal defense is layered correctly (absolute reject → lexical prefix → realpath re-verify → uniform 404); Range parsing is RFC-correct incl. suffix/`bytes=-0`/416/empty-file; stream error + client-disconnect fd cleanup handled.
- **images.ts:** magic-byte sniff authoritative over declared mime; blob path is server UUID; daily Vision cap checked before the Claude call (cap check is TOCTOU-racy across concurrent uploads but the limiter bounds the overshoot — not worth a finding); Vision call outside the tx.
- **Expensive-route limiter placement:** every Claude-calling route (`enrich`, `grade-writing`, `lemmatize`, `conversation` messages/stream, `grammar/identify`, `grammar-drill` gen/submit, `images/ocr`, `diagnostic` gen) is on `expensiveLimiter`; SSE disconnect aborts upstream; the leaked-`final`-rejection case has a catch attached.
- **Division traps:** `writing.ts:155` divides by `max_total`, guarded by `ck_writing_attempts_max_total_positive CHECK (max_total > 0)` (mig 038); `topik.ts:595` divides by a GROUP BY count (>0 by construction); `topik.ts:993` divides by `totalItems` after the empty-set 404. `100.0 *` used, so no integer-division truncation anywhere.
- **grammar Bank category (the historic 500):** fixed for real — migration 034 dropped `ck_grammar_entries_category_known` and the new `ck_grammar_entries_category_len (1..40)` matches the Zod bound.
- **topik attempt body:** already INT4-bounded (`topik.ts:633-649`) with a picks-count cap — the model the finding-3 sites should copy.
- **Unbounded-LIMIT reads:** `GET /hanja` (char pool), `GET /ttmik/lessons`, `GET /iyagi/episodes`, `GET /grammar/bank`, `GET /images` return whole sets without LIMIT — all are small closed corpora or single-user-owned rows; documented as deliberate in ttmik. Not a defect.

## Suggested fixes (smallest-diff)

1. **#1/#2:** add `.max()` sanity on cumulative effect is impossible client-side — instead map pg `22003`/`22008`/`22007` to 400 in `errorHandler` (one switch on `err.code`), and/or validate `date` with a real-calendar refine (`!isNaN(Date.parse(v))` + round-trip check). For #1 also consider widening `minutes_studied` to `NUMERIC(8,2)` or clamping in the upsert.
2. **#3:** one shared `BigintIdSchema = z.coerce.number().int().positive().max(Number.MAX_SAFE_INTEGER)` (and `Int4Schema … .max(2_147_483_647)` for INTEGER columns) in `middleware/validate.ts`; swap the ~12 sites.
3. **#4:** replace the raw message with a fixed string (`"fail"`), keep the detail in the log line only.
4. **#5:** send fixed messages in SSE error frames; keep `err.message` in `req.log` only (`recovered_text` can stay).
