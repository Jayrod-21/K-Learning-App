## Real bugs, prioritized

1. **B-014 — Review flashcard flip leaks the next card's answer (P2, highest priority to fix).** Happens on literally every rating tap in the Review flow, which is one of the core daily-use screens testers will hit constantly. Fix needs to target the actual mechanism found here (CSS transition racing the content swap), not the originally-suspected React-state timing — e.g. delay the content swap until the transition's `transitionend` fires, or reduce/skip the transition duration when advancing to a new card id, or key `Flashcard`'s face content so the back face never renders the *next* card's data while `flipped` is still animating away from `true`.
2. **B-015 — Reference "This Week" grammar column overflows off-screen (P2).** Visible immediately to anyone who opens Reference and has grammar suggestions loaded (test data has these). Needs the CSS-grid `min-width:0`/wrap fix at minimum; tabs are the fuller fix per the original ticket.
3. **B-007 (residual) — Diagnostic results header shows a fixed "5 min ago"/"Level 4" regardless of the real retake (P3, downgraded from P2).** The data itself is now correct after the B-006/B-008 review pass fixed the underlying snapshot flow — only the two literal strings are wrong. Cheap fix: derive from `snapshot.completedAt`/`snapshot.referenceLevel` (or equivalent field) if present, otherwise drop the specific claims.
4. **B-016 — `expensiveLimiter` 429 body has no `retry_after` (P3).** Low urgency for a 1-4-friend test group (unlikely to actually hit the expensive rate limit), but cheap to fix given the client-side plumbing already exists for the 423 case — just add `retry_after: Math.ceil(windowMs/1000)` (or compute from the store) to `buildExpensive`'s message.
